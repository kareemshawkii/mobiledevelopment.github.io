How I write clean, scalable code

Each layer has one job and depends on the layer below only through an interface, so features can grow without rewrites.

PresentationWidgets and Cubits. No business rules, no HTTP calls.
DomainEntities and repository interfaces.
DataAPI client, cache and repository implementations.
  • One reason to change per class (SOLID).
  • Dependency injection wires implementations, so tests can swap in fakes.
  • Immutable states keep every screen predictable: loading, loaded, error.
  • Errors are values, handled in one place instead of scattered across widgets.
abstract class RequestsRepository {
  Future<Result<List<Offer>>> getOffers(String id);
}

class OffersCubit extends Cubit<OffersState> {
  OffersCubit(this._repo) : super(OffersState.loading());
  final RequestsRepository _repo;

  Future<void> load(String id) async {
    emit(OffersState.loading());
    final r = await _repo.getOffers(id);
    emit(r.when(success: OffersState.loaded,
                failure: OffersState.error));
  }
}
// one place handles an expired session
onError: (e, handler) {
  if (e.response?.statusCode == 401) {
    _session.expire(); // clear tokens, go to login
  }
  handler.next(e);
}

Real-time without the mess

Chat, offers and notifications arrive live. The connection lives in one service that exposes streams, and the Cubits simply listen. Click any diagram to enlarge it.

  • One SignalR service owns the connection, so screens never touch sockets directly.
  • Messages are validated first, then stored and delivered, and the conversation list updates instantly.
  • App in the background? The same event goes out as a push notification through FCM and opens the right screen.
  • Live negotiation: offers and replies appear without refreshing.

Smart and safe

I connected the app to a two-layer AI moderation service, so people cannot swap phone numbers and take deals off the platform.

  • Layer 1: fast pattern checks reject obvious contact details.
  • Layer 2: a machine-learning model scores everything else. Uncertain messages are saved to improve the model.
  • Sessions: JWT, multi-step OTP and automatic sign-out when a token expires.
  • OCR: document verification workflow for technicians.
